## Record a single lineage event

Receive and commit a single lineage event to a durable database-backed intake queue using the [OpenLineage](https://github.com/OpenLineage/OpenLineage/blob/main/spec/OpenLineage.json) standard. Derived lineage projections are processed asynchronously and may not be visible immediately. There is no application-level event-count cap; database capacity applies. Acceptance confirms only that the event was committed to the intake queue. The queue retries database projection failures and can ultimately dead-letter an event after repeated failures. Search indexing and run-transition listener delivery happen after the queue item is acknowledged and are best effort: they have no durable delivery guarantee, may be missing, concurrent, or out of order, and are not retried by the intake queue. Any 5xx response during queue admission is commit-indeterminate: the queue transaction may already have committed even if Marquez did not observe the commit result. Clients that retry must tolerate duplicate events.
